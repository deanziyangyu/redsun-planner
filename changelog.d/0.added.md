The push-broom plan accepts optional host progress and post-collection
validation callbacks for each strip. Acquisition hosts can report frame
progress and reject a domain-level terminal result after collecting available
geometry and asset documents, preserving evidence while marking the run failed.

Add `planner.acquisition_space`, a pure model of the stage-velocity, exposure
and detection-width acquisition space: typed corner taxonomy and example
trajectories, caller-declared envelope classification, kinematic and
dimensionless metrics, typed measurement-feasibility verdicts, and utility
ranking by ideal unique-area throughput. It emits no device commands or plan
messages.

Add `planner.simulation`, a deterministic mock estimate of a two-round
search-and-image run: overlapping serpentine survey tiles, mock target
positions, a trapezoidal stage-travel model, focused revisit settings, and a
JSON-safe report with travel/imaging time, area throughput, targets per hour and
the equivalent continuous operating points. It reads no pixels and asserts no
device capability.

Add `planner.search_imaging`, the two-round search-and-image workflow: an
overlapping survey recipe and a focused revisit recipe built on the acquisition
model, serpentine survey geometry with stitching context, snap-based Bluesky plan
generators with distinct round metadata, and simulation-based throughput and
corner estimation. Detection, candidate selection and stitching remain
host-owned; the survey may run at the same magnification as the focused round.

Add the `planner` command-line entry point, also available as
`python -m planner`, with `simulate`, `validate` and `diff` commands, a strict
JSON specification, human and `--json` reports, an optional report file, and
stable exit codes for valid, invalid and unparseable input.

Report per-sub-scan metrics for the dual-scan workflow: each round now reports its area, duration, throughput, seconds per position and travel/exposure fractions, with an averaged and combined view across the survey and focused rounds. The CLI prints both blocks and the JSON report exposes `sub_scans` and `averaged`.

Add the adaptive broom timing model (`planner.broom`): regular-cruise and regular-dwell baselines, the time added by slowing at samples, the time saved by speeding between them, ramp and command-delay decomposition, and edge dwell with half-FOV overscan. Add `planner compare`, which reports the measured-readback and speed-blend-replay scenarios for a 2x2 mm field.

Add photobleaching reporting for the dual snap scan: the overview coverage count and prior exposure on each sample, the photobleaching cost relative to the focused exposure, and an optional log-linear retained-brightness/loss fraction for a declared time constant. The CLI reports prior exposure, cost and retained brightness; the JSON report exposes them as `photobleaching`.

Add self-contained HTML throughput pages for the planner: `planner simulate --html` and `planner compare --html` write inline-CSS/SVG charts for wall time, sub-scan throughput, photobleaching and the comparison table, with no JavaScript or network request.

Add operating-space trajectory maps to those pages: three `v`/`T_e`/`W` projections with the dual-snap survey and focused points, the adaptive broom dwell-ramp-cruise-ramp-dwell path, corner labels when an envelope is declared, and low/high bands from the envelope thresholds.

Add a `--envelope` option to `planner compare` so a declared low/high acquisition envelope can shade the operating-space map and supply its corner labels without changing timing.
